# Date the Twins

A dating site for twins who want to go on a **double date with another pair of twins**.

- **Landing page** (`/`): features one pair of twins with Hinge-style profiles (photos, info, and prompts) and a call to action to apply.
- **Application builder** (`/apply`): a 5-step wizard. Applicants describe themselves as a pair, then each twin builds a profile (2–6 photos and 3 prompts), then they answer one prompt together. They preview the joint profile exactly as it will look, confirm they're 18+, and submit. Text progress autosaves in the browser.
- **Admin dashboard** (`/admin`, password protected): the featured twins review applications, mark each one **Like / Maybe / Pass**, add private notes, see contact info, and delete applications.

Stack: Node.js + Express, SQLite (built into Node, no native build step), and plain HTML/CSS/JS with no frontend build step.

## Run it locally

Requires **Node.js 22.13+** (`node -v`).

```bash
npm install
cp .env.example .env        # then edit ADMIN_PASSWORD
npm start                   # or: npm run dev  (auto-restarts on changes)
```

- Site: http://localhost:3000
- Admin: http://localhost:3000/admin. Username `admin`, password from `ADMIN_PASSWORD`. If you don't set one, local dev uses `changeme`.

Run the tests with `npm test`.

## Customize the featured twins

Everything on the landing page comes from **`content/twins.json`**: names, ages, bios, prompts, photos, headline, and site name. You don't need to touch any code.

1. Put your friends' photos in `public/images/twins/` (JPG/PNG/WEBP; portrait 4:5 looks best, e.g. 1200×1500).
2. Update the `photos` paths in `content/twins.json`, e.g. `"/images/twins/jordan-1.jpg"`, and set `pairPhoto` for the hero image (landscape ~5:4).
3. Refresh the page. The JSON is re-read on every request.

The generic placeholder images live in `public/images/placeholders/` and are generated by `node scripts/make-placeholders.js`.

The prompt lists for applicants, photo limits, and minimum age are in `src/options.js`.

## Where data lives

- Applications: SQLite database at `data/app.db`
- Applicant photos: `data/uploads/` (only viewable when logged in as admin)

`data/` is git-ignored, so applicant data never ends up in the repo. Set `DATA_DIR` to move it somewhere else.

## Deploying (GitHub → web host → your domain)

This repo is ready to deploy to any host that runs Node and offers a **persistent disk**. The database and photos are files, so they need a disk that survives restarts.

**Render** (simple option):
1. New → Web Service → connect this GitHub repo.
2. Build command: `npm install`. Start command: `npm start`.
3. Add a **Disk** (e.g. 1 GB) mounted at `/var/data`.
4. Environment variables: `NODE_ENV=production`, `ADMIN_PASSWORD=<long random password>`, `DATA_DIR=/var/data`.
5. Settings → Custom Domains → add your domain and follow the DNS instructions. HTTPS is automatic.

**Railway** or **Fly.io** work the same way: attach a volume, set `DATA_DIR` to its mount path, and set `ADMIN_PASSWORD` and `NODE_ENV=production`.

Notes for production:
- In production the admin is **disabled until `ADMIN_PASSWORD` is set**.
- Admin uses HTTP Basic Auth, which is fine over HTTPS (all of the hosts above provide it).
- Submissions are rate-limited to 10 per hour per IP.
- Back up `DATA_DIR` occasionally.

## Project layout

```
server.js              Express app: API, uploads, admin auth, static files
src/options.js         Prompt lists + limits (shared with the browser via /api/options)
src/validate.js        Server-side validation of applications
src/db.js              SQLite storage
content/twins.json     Featured twins (edit me!)
public/                Static site: index.html, apply.html, admin.html, css/, js/, images/
scripts/               Placeholder image generator
test/                  API tests (node --test)
```
